# Software Requirements & Architecture Specification
**Application Name:** Distributed Office Network Manager  
**Version:** 1.1.0  
**Stack:** Angular (Latest), Firebase, Tailwind CSS  

---

## 1. Technology Stack
*   **Frontend Framework:** Angular (v17/v18) with Standalone Components.
*   **UI/Styling:** Tailwind CSS (for rapid, responsive, and customizable UI design).
*   **Backend & Database:** Firebase Firestore (NoSQL Document Database).
*   **Authentication:** Firebase Auth.
*   **Storage:** Firebase Cloud Storage (for letter/document uploads).
*   **Offline/Sync capability:** Firebase Firestore IndexedDB Offline Persistence + Angular PWA (Service Workers).
*   **State Management:** NgRx SignalStore (lightweight state management for Angular).

---

## 2. Core Architecture & Mechanisms

### 2.1 Offline-First & Database Sync
The app must function flawlessly without internet connectivity in remote office locations.
*   **Firestore Offline Persistence:** Enabled on app initialization. Read/Write operations are executed against the local IndexedDB cache first. 
*   **Syncing:** When the network reconnects, Firebase SDK automatically syncs local changes to the cloud database and fetches new server data.
*   **File Uploads:** Files uploaded while offline queue locally and automatically upload to Firebase Cloud Storage once the network returns.

### 2.2 Multi-Location & Role-Based Access Control (RBAC)
*   **Locations (Places):** Users belong to an array of `location_ids`. Data queries always filter based on the user's assigned locations.
*   **Firebase Custom Claims:** Used to store user roles and locations securely to prevent unauthorized data access at the database rules level.

### 2.3 Dashboard Architecture
*   **Main Global Dashboard:** A centralized overview for top-level management showing aggregated metrics across all accessible modules (e.g., total active customers, pending approvals, total unresolved issues).
*   **Module-Specific Dashboards:** Every module (HR, Land, Letters, etc.) has its own dedicated dashboard showing granular analytics, recent activities, and metrics specific to that domain.

## 3. Module Specifications

### 3.1 Authentication & User Management
*   **Login:** Email/Password via Firebase Auth.
*   **User Assignment:** Assign users to one or multiple physical places/branches.

### 3.2 Settings & Configuration Engine (Core Admin Module)
This module dictates the behavior, data structure, and access levels of the rest of the application.
*   **Dynamic Field Management:** Admins can dynamically add or remove data fields (Text, Number, Dropdown, Date) for **all core modules** (Customers, HR, Land, Work Plans, Letters).
*   **Module Access Control:** Dynamically configure which modules are visible and accessible to specific Users or Roles (e.g., hiding the HR module from Land Officers).
*   **Issue Type & Document Mapping:** Specifically for the Land module, Admins can create an `issue_type` (e.g., "Boundary Dispute", "Transfer of Ownership") and define a specific checklist of `required_documents` that the system will enforce when that issue type is selected.

### 3.3 Customer Registration
*   **Module Dashboard:** Shows total registered clients, recent registrations, and registrations by branch.
*   **Features:** Basic CRUD + dynamic fields injected from the Settings module.

### 3.4 HR Management
*   **Module Dashboard:** Shows employee headcount, today's attendance/leave overview, and pending HR approvals.
*   **Features:** Employee profiles, leave requests, department assignments + dynamic fields.

### 3.5 Land Management (Expanded)
*   **Land Dashboard:** Shows total land parcels registered, unresolved land issues by division, and taxation revenue summaries.
*   **Land Records:** Manage land details, deeds, plot sizes, and ownership.
*   **Land Issues Management:**
    *   **Workflow:** Track disputes, legal issues, or subdivision requests.
    *   **Data Points:** Linked Customer, Issue Type, Division, Address, Job Status (e.g., Open, In Progress, Resolved).
    *   **Dynamic Requirements:** When a user selects an `issue_type`, the UI automatically pulls the `required_documents` checklist defined in the Settings module.
    *   **Approval & Recommendation:** Built-in workflow for higher-ups to add remarks, recommend actions, and officially approve/resolve the issue.
*   **Taxation:** Track property/land taxes, payment history, and generate tax status reports linked to specific land records.

### 3.6 Work Plan & Approval Workflow
*   **Module Dashboard:** Overview of Draft vs. Pending vs. Approved work plans.
*   **Features:** Multi-level approval chains (Branch -> Regional). Track who approved/rejected plans with timestamps + dynamic fields.

### 3.7 Letter Management & Document Upload
*   **Module Dashboard:** Metrics on incoming vs. outgoing correspondence and pending actions.
*   **Features:** Log letters, scan/upload PDFs via Cloud Storage + dynamic fields.

// Core Collections Overview

1. /users
   - uid (string)
   - roles (array of strings)
   - places (array of string IDs)
   - accessible_modules (array of strings - controlled via Settings)

2. /dynamic_schemas
   - schema_id (string)
   - target_module (string - e.g., 'customer', 'hr', 'land')
   - fields (array: { name, label, type, required })

3. /settings_issue_types
   - issue_type_id (string)
   - name (string - e.g., "Deed Transfer")
   - required_documents (array of strings - e.g., ["Original Deed", "Survey Plan", "NIC Copy"])

4. /land_records
   - land_id (string)
   - owner_customer_id (string)
   - dynamic_data (object) 

5. /land_issues
   - issue_id (string)
   - land_id (string)
   - customer_id (string)
   - issue_type_id (string - maps to settings_issue_types)
   - division (string)
   - address (string)
   - uploaded_documents (object - tracks which required docs are uploaded)
   - job_status (string)
   - recommendation (string)
   - approval_chain (array of approval objects)

6. /land_taxes
   - tax_record_id (string)
   - land_id (string)
   - amount_due (number)
   - amount_paid (number)
   - year (number)
   - status (string - Paid, Overdue)
